# We Vetted 2000 AI Skills Before They Reached Developers

*Program title: We Vetted 2,000 AI Skills Before They Reached Developers*

**Speakers:** [Lucas Palma](../speakers/lucas-palma.md)

**Org:** Nubank

**Track:** AI in Finance &nbsp;|&nbsp; **Day/Room:** Day 4 — Session Day 3 &middot; Track 3 &nbsp;|&nbsp; **Duration:** 16m 24s

[Watch on YouTube](https://www.youtube.com/watch?v=iKQ78wyJEXU)

## Summary

Lucas Palma, product security manager at Nubank, argues that AI skills (bundled instructions and context shipped to coding agents) are not configuration files but supply chain dependencies, and should be governed like packages and containers. He describes Skill Vector, an internal tool that gates skills before they land in Nubank's internal marketplace: engineers can run it locally, and a CI step re-runs deterministic regex-based checks plus an LLM review for behavioral risks, posting findings as PR comments and emitting SARIF into the company's vulnerability management program. Across a baseline of over 2,000 skills scanned, the team found more than 1,500 risks, remediated about 1,000, and blocked a small number outright. The talk is most useful for platform and security teams in regulated environments who need a concrete, low-friction review pipeline for skills, plugins, MCP servers, rules, and hooks. It also flags a subtle failure mode: skills that instruct the model to 'ask for confirmation' where the agent confirms with itself, giving the appearance of a human in the loop without one.

## Key Points

- AI skills look like configuration but behave like supply chain dependencies, so the modern software supply chain now includes skills, plugins, MCP servers, agent rules, and hooks alongside packages, containers, and models.
- The threat model is that a skill author steers the code another engineer's agent generates, which can introduce hardcoded tokens that leak into logs, destructive shell commands, unwanted file modifications, and over-broad permissions.
- Nubank centralizes distribution through an internal plugin/skill marketplace so there is a single canonical boundary where security review can be enforced.
- Skill Vector runs at two points — locally during authoring for fast iteration, and again in CI on the upload pull request — because the team cannot assume the engineer ran the latest version locally.
- The scanner is deliberately hybrid: deterministic regex checks for easy patterns, plus LLM review where behavioral context is needed, since LLM verdicts vary with temperature and are not reliably repeatable.
- Findings are surfaced as comments on the same PR that uploads the skill and exported as SARIF so they feed existing security tooling and the vulnerability management program.
- Over a baseline of 2,000+ skills the team identified more than 1,500 risks, saw roughly 1,000 remediated immediately, and blocked a few high-risk skills before marketplace distribution; a retroactive historical scan surfaced further risks in pre-existing skills.
- A prompt-level 'ask for confirmation' instruction is not a real approval gate — the agent may satisfy the confirmation itself — so the team scans for genuine human-in-the-loop enforcement via tool-level approval gates and hooks.
- Lessons that did not work well included treating all shell commands as equally risky, weak low-context signals that created noise, warnings that only mattered in production rather than locally, and findings shipped without clear remediation guidance.

## Positions

- AI skills should be governed as supply chain dependencies rather than as configuration files. ([1:07](https://www.youtube.com/watch?v=iKQ78wyJEXU&t=67s), confidence: stated)
- Security effort should protect the entire developer workflow, not just the generated code. ([1:07](https://www.youtube.com/watch?v=iKQ78wyJEXU&t=67s), confidence: stated)
- A skill author effectively controls the code generated on other engineers' machines, which is a distinct and dangerous trust transfer. ([3:09](https://www.youtube.com/watch?v=iKQ78wyJEXU&t=189s), confidence: stated)
- Deterministic scanning alone is insufficient and LLM review alone is unreliable, so a hybrid of both is required; LLM verdicts vary with temperature. ([7:46](https://www.youtube.com/watch?v=iKQ78wyJEXU&t=466s), confidence: stated)
- Local scanning must be re-enforced in CI because you cannot ensure the engineer ran the checks or ran the latest version. ([6:55](https://www.youtube.com/watch?v=iKQ78wyJEXU&t=415s), confidence: stated)
- Findings should be delivered in the same pull request that uploads the skill, because co-locating feedback improves usability. ([7:46](https://www.youtube.com/watch?v=iKQ78wyJEXU&t=466s), confidence: stated)
- Nubank scanned over 2,000 skills, found more than 1,500 risks, saw about 1,000 remediated immediately, and blocked a few before marketplace distribution. ([9:38](https://www.youtube.com/watch?v=iKQ78wyJEXU&t=578s), confidence: stated)
- A prompt instruction to 'ask for confirmation' does not constitute a human in the loop, because the agent can satisfy the confirmation itself. ([12:33](https://www.youtube.com/watch?v=iKQ78wyJEXU&t=753s), confidence: stated)
- Treating all shell commands as equally risky produced poor results; risk must be graded per command. ([11:47](https://www.youtube.com/watch?v=iKQ78wyJEXU&t=707s), confidence: stated)
- Low-context, weak signals cause more trouble than they are worth in a skill scanner. ([11:47](https://www.youtube.com/watch?v=iKQ78wyJEXU&t=707s), confidence: stated)
- Findings without clear remediation guidance are counterproductive. ([12:33](https://www.youtube.com/watch?v=iKQ78wyJEXU&t=753s), confidence: stated)
- The same review approach generalizes to plugins, MCP servers, agent rules, and hooks, though with different risk classes. ([13:43](https://www.youtube.com/watch?v=iKQ78wyJEXU&t=823s), confidence: stated)
- Third-party skills downloaded from outside should be routed through the internal marketplace so they get scanned before use. ([15:10](https://www.youtube.com/watch?v=iKQ78wyJEXU&t=910s), confidence: stated)
- A single canonical marketplace is a fragile chokepoint because teams can spin up other marketplaces, requiring proactive discovery. ([12:33](https://www.youtube.com/watch?v=iKQ78wyJEXU&t=753s), confidence: implied)
